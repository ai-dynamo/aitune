<Indent>

Build and validate a backend with standardized error handling and logging.

This method encapsulates the common workflow shared by all strategies:
deep-copy the backend, build it, run correctness checks, and handle failures.

**Parameters:**

<ParamField path="backend" type="Backend">
[`Backend`](../backend/backend.mdx#aitune-torch-backend-backend-Backend) — Backend to build (will be deep copied).
</ParamField>

<ParamField path="module" type="nn.Module">
Module to tune.
</ParamField>

<ParamField path="name" type="str">
Module name.
</ParamField>

<ParamField path="graph_spec" type="GraphSpec">
[`GraphSpec`](../module/graph_spec.mdx#aitune-torch-module-graph_spec-GraphSpec) — Graph specification.
</ParamField>

<ParamField path="samples" type="SampleStore">
[`SampleStore`](../module/sample_store.mdx#aitune-torch-module-sample_store-SampleStore) — Recorded samples.
</ParamField>

<ParamField path="device" type="torch.device">
Target device.
</ParamField>

<ParamField path="cache_dir" type="Path">
Cache directory for this module/graph.
</ParamField>

<ParamField path="raise_on_failure" type="bool" default="False">
If True, re-raise the original exception instead of returning None.
</ParamField>

**Returns:** [`Backend`](../backend/backend.mdx#aitune-torch-backend-backend-Backend) `| None`

The built and validated backend, or None on failure.

<Badge>abstract</Badge>

Tune a torch module with the provided graph specification and samples.

Note: each tuning operation should do a deep copy of a backend as tuning could be called multiple times for the
same module i.e. if there are different graph specs

**Returns:** [`Backend`](../backend/backend.mdx#aitune-torch-backend-backend-Backend)

The tuned and activated backend.

**Raises:**

- `RuntimeError`: if the backend fails any check.


</Indent>
