<Indent>

Export a module to ONNX through AITune's flat tensor interface.

For ``module(x, state={"bias": bias})`` returning ``{"result": x + bias}``, the artifact
has tensor inputs for x and bias and one tensor output for result. Names come from recorded paths;
Python containers and non-tensor sample values are handled by the adapter during export.
Runtime code must supply the named tensors and restore the original output structure.

Both export modes use the same prepared adapter. Dynamo receives Torch dynamic-shape constraints;
the legacy tracer receives ONNX dynamic-axis annotations. The selected mode is used without fallback.
Export returns the artifact path after ONNX structural validation, which does not establish numerical
equivalence with the original module. An incomplete artifact is removed on failure when possible.

User tensor outputs precede internal mutation outputs in the graph's forward effects specification order.
For ``cache[0] = x + 1; return x * 2``, the two outputs carry the user result and updated cache.
Runtime restoration consumes the second internally. Legacy tracing annotates varying state axes
from post-call metadata, since an update can create a tensor absent from the original inputs.

**Parameters:**

<ParamField path="output_path" type="Path">

</ParamField>

<ParamField path="use_dynamo" type="bool" default="False">

</ParamField>

<ParamField path="opset_version" type="int | None" default="None">

</ParamField>

Declare dynamic axes for outputs that carry changed input tensors.

Use post-call bounds because a mutation can create or resize a tensor, for example replacing
a None cache slot with an input-dependent result. With observed sizes (2, 4) and (3, 4), axis
zero of that internal state output is dynamic even though no pre-call cache tensor existed.
Ignore missing post-call specifications and static axes. Only extra mutation outputs are added
here; a changed tensor already returned as a user output uses the ordinary output annotations.


</Indent>

<Indent>

Export, sort, and save the prepared adapter with Dynamo.

Request an in-memory ONNX program so dependency ordering can be repaired before serialization.
The existing unbind/Split optimizer workaround requires producers before their consumers.
Save with external tensor data enabled so large weights can be stored outside the graph file.


</Indent>
