Shared tools for exporting modules through a flat tensor interface.

Models accept Python structures, while AITune uses ordered tensors as the compiled interface.
Recorded metadata defines the same order for example inputs, shape constraints, and outputs.
The adapter reconstructs the Python call inside the exported module, keeping backend code
independent of the original argument structure.

The adapter also exposes recorded tensor mutations as outputs. Backends use GraphSpec's forward effects
specification to apply those changes to current inputs and restore the Python result. See
docs/guides/advanced/execution_graphs.md for the flat interface design example.

Torch and ONNX export share this implementation so argument reconstruction, tensor ordering, and
shape rules stay aligned with inference. ONNX execution and source-model metadata live separately
in aitune.torch.libs.onnx.runtime and aitune.torch.libs.onnx.model_info; existing ONNX artifacts bypass export.

Export a module to ONNX through AITune's flat tensor interface.

For ``module(x, state={"bias": bias})`` returning ``{"result": x + bias}``, the artifact
has tensor inputs for x and bias and one tensor output for result. Names come from recorded paths;
Python containers and non-tensor sample values are handled by the adapter during export.
Runtime code must supply the named tensors and restore the original output structure.

Both export modes use the same prepared adapter. Dynamo receives Torch dynamic-shape constraints;
the legacy tracer receives ONNX dynamic-axis annotations. The selected mode is used without fallback.
Export returns the artifact path after ONNX structural validation, which does not establish numerical
equivalence with the original module. An incomplete artifact is removed on failure when possible.

User tensor outputs precede internal mutation outputs in the graph's forward effects specification order.
For ``cache[0] = x + 1; return x * 2``, the two outputs carry the user result and updated cache.
Runtime restoration consumes the second internally. Legacy tracing annotates varying state axes
from post-call metadata, since an update can create a tensor absent from the original inputs.

**Bases:** `Module`

Adapt a structured module call to flat tensor inputs and outputs in recorded order.

Flattening is the explicit interface shared by export and backend execution. It separates
tensor computation from Python containers, whose structure and identity must be restored outside
the compiled runner. User tensor outputs come first, followed by changed input tensors that the
forward effects specification needs for state restoration and that are absent from the user outputs.

Non-tensor arguments come from the recorded sample. Compatible inputs use a prepared PyTree
recipe to keep reconstruction simple for strict Torch Export. Otherwise, recorded locators
reconstruct the arguments, including custom objects supported by Locator but unknown to PyTree.
This fallback preserves reconstruction support; export still depends on the module and exporter.

Example:
    For a module whose forward returns ``{"result": (x + state["bias"]) * state["scale"]}``,
    preparation from ``module(x=x, state={"bias": bias, "scale": 2})`` records this interface:

    ```python
    Flat inputs:   (x, bias)
    Rebuilt call:  module(x=x, state={"bias": bias, "scale": 2})
    Flat outputs:  (result,)
    ```

    Each invocation supplies current tensors in the recorded order. The scale stays 2 because it
    comes from the sample, and the call stays keyword-based. This example has no input mutations.
    Backend restoration rebuilds the caller's Python output structure from the user tensor results.

Mutation outputs:
    For ``cache[0] = x + 1; return x * 2`` with ``cache=[None]`` in the sample, flat inputs are
    ``(x,)`` and flat outputs are ``(x * 2, x + 1)``. Appending the updated cache tensor keeps an
    otherwise unreturned assignment visible outside the compiled graph. The backend applies it to
    the caller's cache before returning the user result. A changed tensor already returned by the
    module uses its existing output slot, so no extra result is needed for that mutation.

Reconstruction rules:
    PyTree is used only when tensor identity and order agree with SampleMetadata and replacing
    tensors with None preserves the tree structure and non-tensor leaf identity. Matching only
    tensor counts could silently associate a flat input with the wrong argument. On mismatch,
    locators reconstruct from a copied template instead. Rebuilt containers isolate ordinary
    list and dict changes between calls; input tensors are references, so tensor writes can still
    affect supplied tensors. Custom-object reconstruction does not guarantee traceability.

Export a module through AITune's flat tensor interface.

The returned program uses the adapter's tensor order, rather than the original Python call layout.
For ``module(x, state={"bias": bias})`` returning ``{"result": x + bias}``, its module accepts
``(x, bias)`` and returns ``(result,)``. Backend integration must restore the Python output structure.
Mutating modules can return additional state tensors described by the graph's forward effects specification;
backends consume these internally to restore input changes before returning user outputs.

Default tracing tries strict export, then non-strict export for modules that strict tracing cannot
capture. Each attempt prepares fresh sample containers and an adapter; the original module is shared,
so this does not roll back changes to module state. An explicit strict setting disables the retry.

**Parameters:**

<ParamField path="use_auto" type="bool" default="True">
Let Torch Export infer relationships for non-batch dynamic dimensions. If False,
use named bounded dimensions; inferred dimensions with matching bounds share a dimension.
</ParamField>

<ParamField path="strict" type="bool | None" default="None">
Select strict or non-strict export. ``None`` tries strict export first and then falls back.
</ParamField>

<ParamField path="fallback_to_dynamic_hints" type="bool" default="False">
Retry rejected explicit constraints with bounded ``Dim.DYNAMIC`` hints.
</ParamField>
